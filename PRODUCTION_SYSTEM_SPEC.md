# CHAIN OF FAILURE — PRODUCTION SYSTEM SPECIFICATION

Version: V1.0 — 2026-10-04
Status: Ready for one-time bootstrap + system demo validation

## Mission

Build a repeatable faceless investigative-documentary production system that can independently go from subject discovery to a finished, professional documentary video without needing the human to supply the topic, research, evidence, visuals, script, voice, edit decisions, or packaging.

## Editorial product

The channel investigates catastrophic failures by reconstructing the chain of decisions, warnings, mistakes, and system failures that turned a situation into a catastrophe.

The chain is the protagonist:

CAUSE → WARNING → DECISION → ESCALATION → POINT OF NO RETURN → FAILURE → INVESTIGATION → LEGACY

## Permanent operating principles

1. Evidence and factual integrity outrank speed.
2. The repo is the operating system; chat memory is not the operating system.
3. Every important claim needs a source trail.
4. Every visual needs a reason to exist.
5. Evidence visuals outrank generic stock.
6. Technical explanation should prefer diagrams, maps, documents, and mechanism visuals when those explain causality better than footage.
7. Synthetic or reconstructed visuals must be explicitly disclosed and must never be presented as authentic evidence.
8. Audio is restrained: voice first, silence second, music third, SFX rarely.
9. The editor competes on mechanism, causality, clarity, and accountability — not spectacle.
10. Rules evolve from evidence and postmortems, not taste.

## Permanent pipeline

DISCOVER → VALIDATE → RESEARCH → EVIDENCE PACK → STORY CHAIN → SCRIPT → ASSET PLAN → ACQUIRE/CREATE → VOICE → EDIT → SOUND → GRAPHICS → QA → RENDER → PACKAGE → PUBLISH → POSTMORTEM → LEARN

## One-time bootstrap

A fresh Muse workspace must read this entire repository, audit the production system, verify the available toolchain, establish the permanent asset library and licensing ledger, create the production template, and only then mark the system `BOOTSTRAP_COMPLETE`.

The bootstrap run MUST NOT start the 2-minute demo until all bootstrap gates pass.

## System validation

After bootstrap, the human gives no topic and no media. Muse must:

- choose a viable subject independently;
- research and collect proof;
- build the story chain;
- write the narration;
- create or acquire the required visual evidence;
- create disclosed reconstructions or diagrams for genuinely missing explanatory visuals;
- generate narration/voice;
- edit a coherent 2-minute documentary sequence;
- mix sound and music according to the Academy;
- render a finished video;
- provide a source/rights/evidence ledger and a production report.

The human judges the rendered result. The repo is then improved from the observed weaknesses.

## Production cadence after validation

Default: one long-form video per week until the system demonstrates repeatable quality. Increase cadence only after quality is stable and the pipeline bottlenecks are understood.

## Non-goals

- no generic AI slideshow generation;
- no fake documents or fabricated evidence;
- no creator-style cloning;
- no blind copying of viral videos;
- no unlicensed stock/audio/templates;
- no bulk downloading that violates a provider's terms;
- no production that depends on undocumented chat context.

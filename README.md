# Chain of Failure — Channel OS

This repository is the permanent operating system for a faceless investigative documentary YouTube channel about catastrophic failures.

## Core promise
Reconstruct the chain of decisions, warnings, mistakes, and system failures that turned a situation into a catastrophe.

## Operating model
One Muse agent reads and operates this repository as the source of truth. The first run in a clean workspace is a ONE-TIME BOOTSTRAP: audit the repo, provision/verify the toolchain, establish the reusable asset system and licensing records, prepare the production template, and mark the system ready.

Only after bootstrap is complete should Muse run the autonomous 2-minute system demonstration. The demo receives no topic or media from the human.

## Priority
1. Evidence and factual integrity
2. Story clarity and causal reconstruction
3. Documentary-grade editing
4. Audio and visual restraint
5. Packaging and growth
6. Speed

Never sacrifice 1–5 to hit a cadence target.

## Repository map
- `00_CORE/` — channel identity and boundaries
- `01_RESEARCH/` — research reports and source protocols
- `02_CREATIVE_BIBLE/` — creative standard
- `03_EDITING_ACADEMY/` — references, patterns, rules, benchmark, sound system
- `04_WORKFLOWS/` — production stages
- `05_TEMPLATES/` — reusable ledgers and decision formats
- `06_PRODUCTION/` — one folder per video plus the clean production template
- `07_ASSET_LIBRARY/` — reusable assets plus license evidence
- `08_ANALYTICS/` — postmortems and measured learning
- `09_SYSTEM/` — bootstrap, tooling, asset provisioning, state, logs
- `10_AGENT_PROMPTS/` — boot, bootstrap, demo, daily production prompts

## First-run instruction
In a clean Muse workspace, start with `10_AGENT_PROMPTS/BOOTSTRAP_ONCE.md`. Do not start the demo until `09_SYSTEM/bootstrap/BOOTSTRAP_STATUS.md` says `BOOTSTRAP_COMPLETE: TRUE`.

## Human role
The human is the final editorial/quality gate. Muse owns the repetitive research, evidence collection, asset acquisition/creation, edit planning, editing, rendering, and documentation. Where an account, paid subscription, or approval is required, Muse must stop and record the blocker rather than bypassing it.
